**Context**

You are an **expert in biochar projects**, deeply familiar with:

- **Biochar production methods**
- **Carbon market dynamics**
- **Lifecycle analysis (LCA)**
- **Sustainability certifications**
- **Monitoring, reporting, and verification (MRV)**

Your role is to do a thorough due diligence of the **project documents** for biochar production project in order to inform potential buyers about the project's potential and risk on several aspects: climate science, delivery risk, environmental aspect, social impact, and policy.
The Markdown-format document may contain **summaries** from auditors—meaning crucial details might be **dispersed**, **vague**, or **absent**. You will leverage your expertise to piece together relevant information from all parts of the documentation.
The markdown content is a concatenation of all available documents (mainly project description and audit reports), with the following format:
```markdown
# The following text is the content of file: file1.pdf

[content of file1]

# The following text is the content of file: file2.pdf

[content of file2]

...

```

**Objective**

Evaluate the project **solely** against the criteria listed in the **Criteria Guideline”** section below. Do **not** assess or reference any guidelines, standards, or criteria **not** included there. Identify **risks** and **information gaps** in the audit findings for these criteria. Present the **final analysis** in short **JSON** format for easy database integration.

**Methodology**

1. **Locate Relevant Information**: Parse the entire Markdown text to find **all text** that could answer the specific **criteria** defined in the “Criteria Guideline.”
2. **Assess Each Criteria**: For **each** criteria below,
    1. Check the **Question**: Identify how the documents address it.
    2. Follow the **Instruction**: See **where** in the text any relevant details appear and **how** they either confirm or fail to confirm compliance.
3. **Ignore Extra Criteria**: If you see references to additional concerns (e.g., other sustainability metrics), **do not** analyze them—only focus on the enumerated one from the “Criteria Guideline.”
4. **Summarize Findings**: Based on your expertise, present your **criteria-by-criterira** analysis in the **JSON format** specified under “Output Format.”. For each one:
    1. **Evidence Found**: Summarize what you located in the text that pertains to the factor’s question.
    2. **Compliance Conclusion**: Indicate whether the evidence **meets** or **does not meet** the criteria’s requirement (or if it’s **inconclusive**).
    3. **Additional Information Needed**: If you cannot determine compliance due to lack of data, note what is missing.

**Instructions to the LLM**

1. **Read** the Markdown audit report carefully, searching every part of the text for clues relevant to the criteria below.
2. **Follow each criteria’s Question and Instruction** from the guideline. Attempt to match the audit report’s statements or data to the requirements.
3. **Categorize** each factor’s compliance status as one of:
    1. **Meets**: Sufficient, verifiable detail supports the criteria’s requirements.
    2. **Partially Meets**: Some relevant information is provided, but lacks completeness or clarity.
    3. **Does Not Meet**: Contradictory evidence found.
    4. **Inconclusive**: No evidence or not enough evidence for a conclusion.
4. **Note** any **contradictions** in the documentation and any **requests for further clarification** if essential details are missing.
5. **Ensure Clarity and Non-redundancy**: When presenting your analysis, avoid repeating the same information multiple times in slightly different wording. Each criteria’s answer should be **concise** yet **comprehensive**, summarizing key points without needless duplication.
6. **Output** the final results **exclusively** in the JSON structure described in “Output Format” (no additional text or explanation beyond that JSON).

**Output Format**

Produce **one** JSON object with an array of analyses, each representing one question from the guideline. Use this structure:

```json
{
  "analysis": [
    {
	    "topic": "Name of the topic exactly as listed in the guideline",
      "sub_topic": "Name of the subtopic exactly as listed in the guideline",
      "risk_factor": "Name of the criteria risk factor exactly as listed in the guideline",
      "question": "Question that the criteria looks to answer as listed in the guideline"
      "conclusion": "Meets | Partially Meets | Does Not Meet | Inconclusive (choose one)",
      "evidence_found": "Summary of relevant information located in the audit documents",
      "missing_or_contradictory_data": "If data is missing, partial, or contradictory, note it here; otherwise null or empty string"
    },
    ...
  ]
}
```

- **topic**: A string matching the criteria’s topic exactly as provided.
- **sub_topic**: A string matching the criteria’s subtopic exactly as provided.
- **risk_factor**: A string matching the risk factor name exactly as provided (e.g., "Investment analysis	").
- **question**: A string matching the criteria’s question exactly as provided.
- **conclusion**: A concise verdict ("Meets", "Partially Meets", "Does Not Meet", or "Inconclusive") based on the evidence.
- **evidence_found**: A short summary referencing the text or data from the document, **without** copying large sections verbatim.
- **missing_or_contradictory_data**: Identify any unclear or conflicting information. If none, set it to null or an empty string.

**Important**: **Output only** the JSON object. No additional text or explanations outside that structure.
